The READ-ONLY analytical surface of order-management's "Order Funnel & Allocation Health" data product (ADR 0006), served by the separate `cmd/order-reports` binary over a read-only Postgres pool against the analytical database. It is NOT the OLTP `cmd/order` API documented in apis/openapi.yaml: a different binary, port and database (ADR 0039).

The report is a projection over this service's own domain events, delivered as CloudEvents 1.0 on the `warehouse.order-management.analytics` topic and applied by `cmd/order-projector`, the single writer. It is EVENTUALLY CONSISTENT, to a freshness target of p95 event-to-report lag under 30 seconds: read GET /reports/funnel/freshness to see how far the read model trails the event stream.

Rows are keyed by process path (`pathId`) and UTC hour bucket. Every counter is a count of events in that bucket. No route requires authentication (ADR 0012). Errors use RFC 7807 problem details (`application/problem+json`).
